Why ob-sync

Serious sync, zero ceremony

Everything a phone-first vault needs to survive reality: shared-storage quirks, dead .git directories, conflicts from a second device, and 2 a.m. panic restores.

⚡

One-command sync

sync = pre-sync backup + commit + fetch + rebase + push, with a clear [ OK ] line for every step. Nothing hidden, nothing silent.

🛡️

Nine layers of defense

Repo-state guards, lock files, checksummed tar backups, fsck health checks, unborn-HEAD handling — every operation is fenced.

Quick start

Up and running in 3 steps

Works on Android (Termux), Linux and macOS. You only need a GitHub repo (private is fine) and 2 minutes.

📱 Android — Termux

1

Install Termux from F-Droid (not Play Store), then install curl:

pkg install curl
2

Run the installer:

curl -fsSL https://raw.githubusercontent.com/CheginiSoroush/obsidian-sync-scripts/main/mobile/install.sh | bash
3

Verify, connect your vault, open the menu:

ob-sync doctor     # 1. verify the environment
ob-sync init       # 2. asks for your GitHub repo URL
ob-sync            # 3. interactive menu — or 18) Init

🖥️ Linux & macOS

1

Clone the repository:

git clone https://github.com/CheginiSoroush/obsidian-sync-scripts.git
cd obsidian-sync-scripts
2

Run the desktop installer:

./desktop/install.sh
3

Init and sync:

ob-sync init && ob-sync sync
Blind pipes: piping installers into bash is convenient but blind. Prefer to inspect first? Read mobile/install.sh or use the git clone method.

Branch injection and vault-escape closed, watchdog timeouts reported honestly, and a character-device log (/dev/full) can no longer hang a run — backported straight from the field-test campaign and covered by 95 human-error attack checks.

Configuration

Two config layers — and your vault carries its own

ob-sync keeps device stuff on the device and vault stuff inside the vault. That split is what makes multi-device sync boring — in the best possible way.

🖥️ Device config — ~/.config/ob-sync/config

Describes this device: which vault is pinned, where backups live, branch overrides. Written by ob-sync init, editable via menu 17) EditConf — and it never leaves the machine. Environment variables (OBS_VAULT, OBS_REMOTE, …) always outrank it.

🪪 Vault identity card — <vault>/.ob-sync/config new in 9.5

Describes the vault: its REMOTE and BRANCH — two keys, nothing else. Written by init / remote, committed with the vault, and re-aligned with origin on every locked run: the card wins over a stale origin.

# .ob-sync/config — committed with the vault
REMOTE=git@github.com:you/MyVault.git
BRANCH=main
git clone git@github.com:you/MyVault.git
ob-sync init      # adopts the clone — remote already known
ob-sync sync      # green on the first run

When several sources disagree, the order is fixed: OBS_REMOTE → the vault's origin → the identity card → the device config (only for its own pinned vault). A vault with none of these refuses honestly and init asks — nothing is ever guessed. Even a deleted .git is recoverable: ob-sync repair rebuilds the metadata from the card's remote.

🔐 No tokens, ever. Neither file stores credentials — only URLs and branch names. Log in once with git's credential helper (git config --global credential.helper store or gh auth login) and every device, cron job and widget reuses it. An automated test asserts the card stays credential-free.

FAQ

Questions people actually ask

Still stuck? The troubleshooting guide and issue tracker are one click away.

Is my data safe? What if something goes wrong?
Every risky operation takes a timestamped, checksummed tar.gz backup first, and restore only rolls back from verified backups. Sync pushes are additive — ob-sync never rewrites published history with force.
Does it ever force-push or lose my commits?
No. Remote integration uses git rebase onto origin/main, so both devices' work survives. Conflicts are surfaced with clear guidance, never buried.
Repair failed on my phone with [FAIL] — what now?
Upgrade first (curl -fsSL https://raw.githubusercontent.com/CheginiSoroush/obsidian-sync-scripts/main/mobile/install.sh | bash). v9.3.0 prints the real underlying error and, on FUSE/sdcardfs filesystems where directory renames fail, falls back to a copy-based install automatically.
How do I connect a brand-new vault?
Open the menu (ob-sync) and pick 18) Init. Confirm the vault path, paste your new GitHub repo URL, and ob-sync initializes git, wires the remote and performs the first sync. Empty directory? It clones. Existing notes? It adopts them.
Does it need root or Obsidian plugins?
No root, no plugins, no daemon. Just Termux (F-Droid build) with git — the installer checks the environment for you via ob-sync doctor.
Which platforms are supported?
Android via Termux, plus native Linux and macOS. Requires Bash 4+. The same script drives all three — mobile/install.sh for Termux, desktop/install.sh elsewhere.
I cloned my vault to a new device — will it just work?
Yes — since v9.5.0 the vault carries its identity in .ob-sync/config: the remote URL and branch travel inside the repository itself. Run ob-sync init once (it adopts the clone), then ob-sync sync — no remote questions asked. And if .git is ever lost, ob-sync repair rebuilds it from the card's remote.
Where are my settings stored — is my token in there?
Two places, and neither holds secrets: the device config (~/.config/ob-sync/config — pinned vault, backups) stays on the machine, and the vault identity card (.ob-sync/config — remote URL + branch) is committed with the vault so clones self-configure. Credentials belong to git's credential helper; an automated test guarantees the card never contains tokens or passwords.

پیکربندی

دو لایهٔ پیکربندی — والت شما هویت خودش را حمل می‌کند

ob-sync چیزهای مربوط به دستگاه را روی دستگاه نگه می‌دارد و چیزهای مربوط به والت را داخل خود والت. همین تفکیک است که همگام‌سازی چنددستگاهی را بی‌دردسر می‌کند.

🖥️ پیکربندی دستگاه — ~/.config/ob-sync/config

این دستگاه را توصیف می‌کند: کدام والت سنجاق شده، بکاپ‌ها کجا ذخیره شوند، شاخهٔ پیش‌فرض. با ob-sync init نوشته می‌شود، از منو با 17) EditConf قابل ویرایش است — و هرگز از دستگاه خارج نمی‌شود. متغیرهای محیطی (OBS_VAULT، OBS_REMOTE و…) همیشه از آن بالاترند.

🪪 کارت هویت والت — <vault>/.ob-sync/config تازه در ۹.۵

خود والت را توصیف می‌کند: REMOTE و BRANCH — فقط دو کلید، نه بیشتر. با init / remote نوشته می‌شود، همراه والت کامیت می‌شود و در هر اجرای قفل‌دار با origin هم‌تراز می‌شود: کارت از یک origin کهنه بالاتر است.

# .ob-sync/config — همراه والت کامیت می‌شود
REMOTE=git@github.com:you/MyVault.git
BRANCH=main
git clone git@github.com:you/MyVault.git
ob-sync init      # کلون را به فرزندی می‌گیرد — ریموت از قبل معلوم است
ob-sync sync      # همان اجرای اول سبز است

وقتی چند منبع با هم ناسازگارند، ترتیب ثابت است: OBS_REMOTE ← origin خود والت ← کارت هویت ← پیکربندی دستگاه (فقط برای والتِ سنجاق‌شدهٔ خودش). والتی که هیچ‌کدام را ندارد صادقانه رد می‌کند و init می‌پرسد — هیچ‌چیز حدس زده نمی‌شود. حتی .git حذف‌شده هم قابل بازیابی است: ob-sync repair متادیتا را از ریموتِ روی کارت بازسازی می‌کند.

🔐 هرگز توکنی در کار نیست. هیچ‌کدام از این دو فایل رمز نگه نمی‌دارند — فقط URL و نام شاخه. یک بار با credential helper گیت وارد شوید (git config --global credential.helper store یا gh auth login) تا همهٔ دستگاه‌ها، cronها و ویجت‌ها از همان استفاده کنند. یک تست خودکار تضمین می‌کند کارت هرگز شامل توکن یا رمز نباشد.

سوال‌هایی که واقعاً پرسیده می‌شود

هنوز گیر کردید؟ راهنمای عیب‌یابی و باگ‌ترکر یک کلیک فاصله دارند.

امنیت داده‌هایم چطور است؟ اگر مشکلی پیش بیاید؟
هر عملیات پرخطر اول یک بکاپ tar.gz با مهر زمانی و checksum می‌سازد، و restore فقط از بکاپ‌های راستی‌آزمایی‌شده برمی‌گردد. pushها افزودنی‌اند — ob-sync هرگز با force تاریخچهٔ منتشرشده را بازنویسی نمی‌کند.
آیا force-push می‌کند یا کامیت‌هایم را گم می‌کند؟
نه. یکپارچه‌سازی ریموت با git rebase روی origin/main است، پس کار هر دو دستگاه زنده می‌ماند. تعارض‌ها با راهنمای شفاف رو می‌شوند، هرگز دفن نمی‌شوند.
repair روی گوشی‌ام با [FAIL] شکست خورد — حالا چه؟
اول ارتقا دهید (curl -fsSL https://raw.githubusercontent.com/CheginiSoroush/obsidian-sync-scripts/main/mobile/install.sh | bash). نسخهٔ ۹.۳.۰ خطای واقعی زیرین را چاپ می‌کند و روی فایل‌سیستم‌های FUSE/sdcardfs که rename دایرکتوری در آن‌ها شکست می‌خورد، خودکار به نصب کپی‌محور برمی‌گردد.
یک والت کاملاً تازه دارم؛ چطوری وصلش کنم؟
منو را باز کنید (ob-sync) و 18) Init را بزنید. مسیر والت را تأیید کنید، URL مخزن تازهٔ گیت‌هاب را بچسبانید؛ ob-sync گیت را راه می‌اندازد، ریموت را وصل می‌کند و اولین sync را انجام می‌دهد. پوشه خالی؟ کلون می‌کند. یادداشت موجود؟ به فرزندی می‌گیرد.
ریشه (root) یا افزونهٔ Obsidian می‌خواهد؟
نه root، نه افزونه، نه daemon. فقط Termux (نسخهٔ F-Droid) با git — نصب‌کننده با ob-sync doctor محیط را برایتان بررسی می‌کند.
روی چه پلتفرم‌هایی کار می‌کند؟
اندروید با Termux، به‌علاوهٔ لینوکس و مکِ بومی. فقط Bash 4+ لازم است. همان یک اسکریپت هر سه را می‌راند — mobile/install.sh برای Termux، desktop/install.sh برای بقیه.
والتم را روی دستگاه تازه کلون کردم — همین‌طوری کار می‌کند؟
بله — از نسخهٔ ۹.۵.۰ والت هویتش را در .ob-sync/config حمل می‌کند: URL ریموت و شاخه داخل خود مخزن سفر می‌کنند. یک بار ob-sync init را اجرا کنید (کلون را به فرزندی می‌گیرد)، بعد ob-sync sync — هیچ سوالی دربارهٔ ریموت پرسیده نمی‌شود. و اگر روزی .git گم شد، ob-sync repair آن را از ریموتِ روی کارت بازسازی می‌کند.
تنظیماتم کجا ذخیره می‌شوند — توکنم آنجاست؟
دو جا، و هیچ‌کدام رمز ندارد: پیکربندی دستگاه (~/.config/ob-sync/config — والت سنجاق‌شده، بکاپ‌ها) روی خود دستگاه می‌ماند، و کارت هویت والت (.ob-sync/config — URL ریموت + شاخه) همراه والت کامیت می‌شود تا کلون‌ها خودشان را پیکربندی کنند. رمزها جایشان credential helper خود گیت است؛ یک تست خودکار تضمین می‌کند کارت هرگز شامل توکن یا رمز عبور نباشد.

به دردتان خورد؟

یک ⭐ در گیت‌هاب فقط دو ثانیه طول می‌کشد و واقعاً کمک می‌کند کاربرهای دیگر Obsidian هم ob-sync را پیدا کنند.
